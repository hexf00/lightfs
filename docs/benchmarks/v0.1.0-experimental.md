# Performance baseline — v0.1.0-experimental

Target: product code `2e7a345` (branch `s31-pack-proto`; later
orchestration commits touch CI/docs and test-only code —
`git diff 2e7a345..6726078 -- src/` shows a single `#[cfg(test)]` test
body change, no production path). Harness: `lightfs-bench` as it exists
in that commit — the same workload and scenario set the CI `perf-smoke`
job runs (200 x 100 KiB small objects, 32 MiB large object, plus raw-S3
comparison scenarios and server-side meta lookups). This is a BASELINE,
not an optimization result: numbers exist so future changes have a
fixed reference. Do not compare them across environments.

## Environment 1 — Linux (controlled, local): Debian aarch64 container

| Item | Value |
| --- | --- |
| Code under test | `2e7a345` (release build, `cargo build --release`) |
| CPU / RAM | colima VZ VM, Apple M1 (aarch64), 4 vCPU, 4 GiB |
| OS / kernel | Debian 12 (rust:1-slim, Docker on colima), Linux aarch64 |
| Rust | 1.85.1 (rust-toolchain.toml pin) |
| MinIO | RELEASE.2025-10-15T17-29-55Z semantics — the HOST's source-built MinIO (same build as CI pin), reached from the container over the colima virtual NIC (192.168.5.2:9000), data on macOS APFS |
| Caches | metadata disabled, data disabled |
| Metadata DB / staging | container tmpfs (no disk variable) |
| Dataset | 200 x 100 KiB + 32 MiB; keys `bench2/obj-XXXXXX`; bucket `lightfs-bench-lin` |
| Passes | 3 consecutive full passes, same bucket (raw results: `docs/benchmarks/raw/bench-run-{1,2,3}.txt`, committed next to this document) |

NOTE the honest caveat: this path crosses a virtual NIC instead of
loopback, so every request carries that fixed extra latency. Absolute
numbers are therefore conservative; the value of this environment is
repeatability, not absolutes.


| Scenario | median (3 passes) | range (min–max) | latency p50 median |
| --- | --- | --- | --- |
| raw-S3 serial PUT+GET | 287 files/s | 250 – 1060 (pass 1 hot-cache outlier) | 3.3 ms |
| raw-S3 par-8 | 1635 files/s | 1563 – 2396 | 3.9 ms |
| lfs serial (200 x 100KiB, product path) | 737 files/s / 72–79 MB/s | 248 – 810 | 1.3 ms |
| lfs par-8 | 2478 files/s / 242 MB/s | 1553 – 2687 | 2.2 ms |
| lfs large full-read (32 MiB) | 388 MB/s | 388 – 392 | 81 ms/obj |
| lfs large 8 MiB-chunked | 369 MB/s | 368 – 383 | 22 ms/chunk |
| lfs large STREAMED-WRITE (32 MiB) | 121 MB/s | 121.2 – 121.8 (<0.5%) | n/a |
| lfs 4 KiB random reads | 1460 files/s / 5.7 MB/s | 1394 – 1495 | 0.68 ms |
| lfs meta lookups | 5508 files/s | 5420 – 5508 (<1.6%) | 0.18 ms |

Readings: the metadata/latency classes are extremely stable across
passes (<2% spread); the serial-write classes swing with the virtual-NIC
and APFS fsync behavior of the host (pass 1 consistently slower) — the
macOS loopback reference below lands in the same range, so the numbers
are internally consistent. No order-of-magnitude anomaly.

## How to reproduce

Linux (container): see the run script shape in
`docs/benchmarks/` history — `cargo build --release` inside
rust:1-slim (aarch64), metadata/staging on tmpfs, `lightfs-bench
--objects 200 --obj-size 102400 --large-mb 32 --lfs-large-mb 32
--scenario "prepare,raw-serial,raw-par8,lfs-serial,lfs-par8,lfs-large,
lfs-chunked,lfs-stream-write,lfs-4k-rand,lfs-meta"`, three passes.

CI: dispatch `ci.yml` on the branch; the `perf-smoke` job uploads its
raw output as an artifact every run.
